## Markdown routes

No extra flag is required.

- Shared API: `GET /api/docs?format=markdown&path=<slug>`
- Page aliases: `/docs.md` and `/docs/<slug>.md`
- `Signature-Agent` on a canonical docs URL requests Markdown.
- Next.js also accepts an unambiguous `Accept: text/markdown` and known AI user agents.
- Mixed `Accept` headers containing `text/html`, `text/*`, or `*/*` stay HTML in Next.js; use the
  `.md` route or API format.
- Successful responses include canonical `Link`, `Content-Location`, and `ETag`. `Last-Modified`
  appears only with an exact source timestamp.
- Markdown starts with page metadata and ends with a Sitemap footer.
- Missing routes return actionable Markdown with suggestions; very high-confidence matches may
  redirect.
- A sibling `agent.md` overrides generated page Markdown.
- Otherwise the runtime uses the agent audience projection of the page.
- Markdown, Ask AI, MCP, `llms-full.txt`, and static export share that projection.

Non-Next adapters need the public forwarder generated by current `init`:

| Framework | Forwarder |
| --- | --- |
| TanStack Start | `src/routes/$.ts` |
| SvelteKit | `src/hooks.server.ts` |
| Astro | `src/middleware.ts` |
| Nuxt | `server/middleware/docs-public.ts` |

Probe examples:

```bash
curl "http://127.0.0.1:3000/api/docs?format=markdown&path=quickstart"
curl "http://127.0.0.1:3000/docs/quickstart.md"
curl "http://127.0.0.1:3000/docs/quickstart" -H "Signature-Agent: https://chatgpt.com"
```

## Audience projections

- Shared content appears in both projections.
- `<Agent>` and `<Audience only="agent">` appear only in the agent projection.
- `<Human>` and `<Audience only="human">` appear only in the human projection.
- `<Agent>` and `<Human>` have fixed audiences; do not add `only`.
- `Audience.only` must be a static `"human"` or `"agent"` literal.
- Invalid/dynamic audience declarations remain shared and are reported by review.
- Audience filtering is representation shaping, not authentication. Never place secrets in any
  audience block or `agent.md`.

Example:

```mdx
# Quickstart

Shared instructions.

<Human>Use the highlighted dashboard control.</Human>

<Agent>Preserve scaffolded paths and verify the command exits successfully.</Agent>
```

## Structured agent contracts

Page frontmatter `agent` may define:

- `tokenBudget`
- `task` and `outcome`
- `appliesTo` with framework, version, package, or locale scope
- `prerequisites`, `files`, and `commands`
- `sideEffects`
- `verification`
- `rollback`
- `failureModes`

```yaml
agent:
  tokenBudget: 900
  task: Install the docs framework
  outcome: The docs route renders locally.
  appliesTo:
    framework: nextjs
    version: ">=16"
    package: "@farming-labs/next"
  prerequisites:
    - The app uses the App Router
  commands:
    - run: pnpm add @farming-labs/docs @farming-labs/next
      description: Install the packages
  verification:
    - run: pnpm dev
      expect: The docs route returns HTTP 200
  rollback:
    - Remove the packages and restore the previous config
  failureModes:
    - symptom: The route returns 404
      resolution: Confirm withDocs wraps the Next.js config
```

Contracts are normalized into Markdown, search/Ask AI context, MCP task tools, and Schema.org
`HowTo`. Review reports unknown or malformed fields and suggests missing outcome, verification, or
recovery details without breaking delivery.

## llms.txt

`llmsTxt` is enabled by default.

```ts
llmsTxt: {
  baseUrl: "https://docs.example.com",
  maxChars: { mode: "warn", chars: 50_000 },
  sections: [{
    title: "API",
    description: "Endpoint and SDK references.",
    match: "/docs/api/**",
    maxChars: { mode: "warn", chars: 25_000 },
  }],
}
```

Routes include `/llms.txt`, `/llms-full.txt`, and well-known aliases. Native public files win.
Compact files link to `.md` pages; full files contain projected content.

- `maxChars.mode` accepts `"warn"`, `"error"`, or `"off"`.
- Sections are opt-in and derive their route from the first matcher.
- Root output lists sections first and excludes matched pages from the root body.
- Set `llmsTxt.apiCatalog: false` to disable API catalog exposure while retaining skill discovery.

## Sitemaps

```ts
sitemap: {
  enabled: true,
  baseUrl: "https://docs.example.com",
  xml: { includeLastmod: true },
  markdown: {
    includeDescriptions: true,
    includeLastmod: true,
    linkTarget: "both",
  },
}
```

Default routes:

- `/sitemap.xml`
- `/sitemap.md`
- `/docs/sitemap.md`
- `/.well-known/sitemap.md`
- shared API sitemap formats

`routePrefix` moves the route family. Static generation writes a manifest and public files;
SvelteKit uses `static/`, other adapters use `public/`. `lastmod` prefers the last git commit and
falls back to filesystem mtime.

```bash
pnpm exec docs sitemap generate --check
```

## Robots

```ts
robots: {
  enabled: true,
  baseUrl: "https://docs.example.com",
  path: "public/robots.txt",
  ai: "allow",
}
```

Runtime adapters serve `/robots.txt` when no static file owns it. The generator targets
`public/robots.txt`, or `static/robots.txt` for SvelteKit. Existing files are preserved unless
`--append` or `--force` is explicit.

Generated policy advertises docs routes, Markdown, llms files, sitemaps, AGENTS.md, skill.md, API
catalog, Agent Skills, MCP aliases, discovery routes, and common AI crawlers. `docs doctor --agent`
reports blocked agent routes or crawlers.

## Structured data

Every docs page emits Schema.org `TechArticle` plus `BreadcrumbList`; task-contract pages also emit
`HowTo`. Absolute URLs reuse a configured sitemap, llms, robots, or Ask AI base URL. No separate
structured-data flag is required.
